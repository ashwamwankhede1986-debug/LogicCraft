1. Executive Summary & Project Architecture

LogicCraft is an integrated multi-subject academic software system engineered for the visual simulation, hardware mapping, algorithmic optimization, and topological validation of digital logic gate circuits. In accordance with the college's Semester III Exam Reform Guidelines, Task 4 completes and unifies the system across four core subjects without creating fragmented subprojects:

  • Programming Lab (C++): Optimization using procedural Searching (Linear vs. Binary), Sorting (Bubble vs. Selection), and Hashing (Prime Modulus 17 with Linear Probing). Adheres strictly to procedural C++ (structs, arrays, pointers, functions, zero OOP).
  • Computer Organization & Architecture (COA): Direct hardware mapping of application logic to 64-bit AMD64 assembly instructions, processor registers (RAX, RCX, RDX, R8), status flags (ZF, SF), and successive-addition propagation delay computation.
  • Computer Graphics (OpenGL): Complete replacement of card-like bounding boxes with authentic ANSI/IEEE Std 91-1984 logic gate symbols (AND, OR, NOT, NAND, NOR, XOR, XNOR) with sub-pixel pin alignment precision.
  • Problem Solving Using OOP (Java): Robust circuit file persistence (.circ format), safe exception handling (missing/corrupted file safety), and custom reusable Generics architecture (ComponentList<T>).
  • Full-Stack Web Layer: Node.js REST API and interactive HTML5 Canvas frontend providing a unified dashboard for live academic demonstrations and viva evaluations.

3. Programming Lab (C++) — Task 4 (CO4 & CO5)

Mandatory Academic Restriction Adhered: Procedural C++ only. No classes, inheritance, polymorphism, encapsulation, or OOP design patterns are used. All structures, arrays, pointers, and functions are second-year viva friendly.

A. Searching Algorithms (CO4)

Located in Cpp/Searching/Searching.cpp (Lines 1–90) and Cpp/Searching/Searching.h:

  • Linear Search (linearSearchById, linearSearchByName): Iterates element-by-element across the array. Comparison count: $C_{\text{best}} = 1$, $C_{\text{worst}} = N$, $C_{\text{avg}} = (N+1)/2$. Handles missing elements gracefully by returning -1.
  • Binary Search (binarySearchById, binarySearchByName): First asserts that the component array is pre-sorted using isSortedById(). Employs logarithmic interval halving. Comparison count: $C_{\text{worst}} = \lfloor \log_2 N \rfloor + 1$.

B. Sorting Algorithms (CO4)

Located in Cpp/Sorting/Sorting.cpp (Lines 1–120) and Cpp/Sorting/Sorting.h:

  • Bubble Sort (bubbleSortComponents): Compares adjacent components and swaps out-of-order elements. Includes an early-termination boolean flag (swapped) to stop immediately if the array is already ordered ($O(N)$ best-case, $O(N^2)$ worst-case).
  • Selection Sort (selectionSortComponents): Identifies the minimum/maximum element in the unsorted partition and places it in position using at most $N-1$ swaps. Ideal for memory architectures where write cycles are costly.
  • Fields Supported: Sorts by Component ID (numeric), Component Name (alphabetic), or Gate Type (functional category), in either ascending or descending order.

C. Hash Table with Linear Probing (CO5)

Located in Cpp/Hashing/HashTable.cpp (Lines 1–243) and Cpp/Hashing/HashTable.h:

  • Structure: ComponentHashTable containing a fixed array of 17 buckets (prime modulus $N=17$).
  • Hash Functions:
    1. Modular Hashing for IDs: $H(id) = |id| \pmod{17}$.
    2. Polynomial Rolling Hash for Strings: $H(s) = \left(\sum_{i=0}^{L-1} s[i] \cdot 31^i\right) \pmod{17}$.
  • Linear Probing Collision Handling: If bucket $H(k)$ is occupied by a different key, probe sequence advances sequentially:
    index = (baseHash + step) % 17.
  • Tombstone Slot Recycling: Deleted records are marked SLOT_DELETED (tombstone), allowing search chains to continue while recycling deleted slots during subsequent insertions.
  • Full-Table Handling: Rejects insertions when table reaches 17/17 capacity, preventing infinite probe loops.

4. Computer Organization & Architecture (COA) — Task 4 (CO4)

Task 4 integrates native 64-bit AMD64 assembly functions with the C++ application, illustrating how high-level logic simulator operations map to physical CPU registers, ALU opcodes, and conditional flags.

A. Assembly Opcode Mapping (`COA/ALP/logic_ops_64.s`)

Conforms to the Microsoft x64 ABI. Function parameters arrive in registers RCX, RDX, R8, and R9; return values are placed in RAX: 

# 64-Bit Logic Gate Evaluation (logic_ops_64.s)
.globl asm_and_64
asm_and_64:
    movq %rcx, %rax       # Load input A into RAX
    andq %rdx, %rax       # Bitwise AND with input B
    ret

.globl asm_mul_successive_addition_64
asm_mul_successive_addition_64:
    xorq %rax, %rax       # Delay Accumulator = 0
    testq %rdx, %rdx      # Check if stages == 0
    jz .L_mul_done
.L_mul_loop:
    addq %rcx, %rax       # Accumulate stage delay (5 ns)
    decq %rdx            # Decrement stage count
    jnz .L_mul_loop       # Branch if stages remaining
.L_mul_done:
    ret

B. Hardware Integration & Processor Verification

Located in COA/Tests/Task4IntegrationTests.cpp (Lines 1–160):

  • Application-to-Processor Mapping (testCOAApplicationProcessorMapping): Evaluates active circuit gates using direct assembly calls, confirming bit-level output parity with hardware.
  • Successive Addition Delay (testArithmeticSuccessiveAdditionDelay): Calculates cumulative circuit propagation delay via assembly loop addition without relying on CPU hardware multipliers.
  • Status Flags & Branching (testProcessorFlagsAndBranching): Demonstrates how CMP and TEST instructions update the Zero Flag (ZF) and Sign Flag (SF) to control conditional branches (JE, JNE).

5. Computer Graphics (OpenGL) — Task 4 (CO4 & Gate Symbols)

Task 4 eliminates rectangular UI card boxes and replaces them with authentic ANSI/IEEE Std 91-1984 logic gate symbols rendered using pure OpenGL vector geometry.

A. ANSI/IEEE Symbol Drawing Techniques (`GateRenderer.cpp`)

  • AND Gate (drawANDGate): D-shaped body featuring a flat input edge on the left and a semi-circular curved output profile on the right, constructed using GL_QUADS and GL_TRIANGLE_FAN.
  • OR Gate (drawORGate): Features an inward concave back arc on the input side and sweeping dual-convex curves meeting at a sharp right apex, drawn using GL_POLYGON and GL_LINE_STRIP.
  • NOT Gate (drawNOTGate): Crisp triangular inverter body (GL_TRIANGLES) with a circular output inversion bubble (drawInversionBubble).
  • NAND, NOR, XNOR Gates: Renders base shapes with an inversion bubble at the output terminal.
  • XOR Gate (drawXORGate): Curved OR body with an additional detached curved arc on the input side.

B. Sub-Pixel Pin Alignment & Wire Connectivity

The GateRenderer::getGatePinPosition() function calculates the exact terminal coordinates for inputs ($A, B$) and output ($Y$). This ensures that connection wires seamlessly snap to pin centers within $\pm 0.001$ coordinate precision across any pan, zoom, or camera transform.

C. Interactive Keys in OpenGL Canvas

  • Press `[7]` (7-Gate Showcase): Arranges all 7 standard logic gate symbols simultaneously on the canvas in two aligned rows for visual inspection.
  • Press `[G]` (Cycle Gate Shape): Morphs the selected gate through all 7 gate shapes dynamically in real-time.

6. Problem Solving Using OOP (Java) — Task 4 (CO4)

Task 4 introduces circuit file persistence and generic data container architecture within the Java desktop subsystem.

A. Circuit File Persistence (`ProjectFileManager.java`)

Located in java/src/logiccraft/file/ProjectFileManager.java (Lines 1–191):

  • Serialization (saveCircuitToFile): Formats complete circuit topology into plain-text .circ files, writing gate metadata, pin states, and wire connection arrays.
  • Deserialization (loadCircuitFromFile): Reads .circ files, parses headers and records, and dynamically reinstantiates gate objects using the polymorphic GateFactory.
  • Exception Safety: Explicitly handles FileNotFoundException for missing files, IOException for read/write errors, and catches corrupted records without crashing the application.

B. Reusable Generic Component Architecture (`ComponentList.java`)

Located in java/src/logiccraft/collections/ComponentList.java (Lines 1–80):

  • Custom generic container class ComponentList<T> providing type-safe storage for circuit components.
  • Implements higher-order predicate filtering: ComponentList<T> filter(Predicate<T> predicate).
  • Integrated into Swing desktop GUI (LogicCraftUI.java) with dedicated toolbar buttons for "Save Circuit", "Load Circuit", and "Filter (Generics)".
